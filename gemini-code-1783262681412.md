# System Directive: Advanced Grading Engine & Data Privacy Overhaul

This directive establishes the structural updates required to handle strict rubric compliance, PII data masking, DepEd MATATAG integration, and compliance-driven data retention policies.

---

## Part 1: Early-Exit Privacy Filter & Handlers

### 1. Short-Circuit Prompt Engineering
*   **[MODIFY]** `server/server.js` — VLM Grading Prompt Execution
    *   **Implementation:** Revise the primary system prompt constraints. Instruct Gemini to treat name detection as a priority validation gate.
    *   **Instruction:** "STEP 1: Scan the essay image for handwritten or typed student names. If a name is detected, immediately short-circuit. Stop evaluation and return exactly `{"privacyViolationDetected": true}`. Do not execute rubric parsing or feedback generation if Step 1 triggers."

### 2. Strict Invalidation & Retake Controls
*   **[MODIFY]** `server/server.js` — Grading Endpoint Response Logic
    *   **Implementation:** If `aiResult.privacyViolationDetected` returns true, purge the asset files from local temp storage (`fs.unlinkSync`) immediately. Return a clean `400 Bad Request` with `privacyViolation: true`. Do not commit an orphaned entry to the database.
*   **[MODIFY]** `src/pages/teacher/BatchUpload.jsx`
    *   **Implementation:** Trap the `400` privacy response. Update the specific file card item status to a distinct `'privacy'` style with an orange/red alert accent. Render a contextual "Retake Image" button directly inside the list interface that clears the row state and lets the teacher clear the entry with a fresh compliance-friendly scan.

## Part 4: Date-Calculated Grade Retention Enforcement

### 1. Contextual Lifespan Anchoring
*   **[MODIFY]** `server/server.js` — Submission Creation Phase
    *   **Implementation:** When generating a record, do not use a blind calendar offset from the current execution date. Query the associated Class entry to extract the baseline `schoolYear` context.
    *   **Calculation:** Calculate the end of that specific academic cycle (e.g., if SY 2026-2027, end date is set to June 30, 2027). Compute `retainUntil` as exactly 1 Year past that anchored point (June 30, 2028) to satisfy real-world grade appeal regulations.

### 2. Protected Purge Transactions
*   **[NEW]** `server/server.js` — `POST /api/admin/archive-grades` & `DELETE /api/admin/purge-grades`
    *   **Implementation:** Enforce clear schema runtime boundaries. The data deletion endpoints must process transactions with an explicit date validation barrier: `where: { retainUntil: { lte: new Date() } }`. Reject attempts to archive or wipe records that fall within their active legal protection window.
